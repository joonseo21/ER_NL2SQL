# 지표·용어 정의 (7-1 검토본)

2026-10-11. Q-08의 실험체 픽률 답변과 D-03·D-05·D-06을 반영한다. 2026-10-17에 2026-10-14 사용자 정의(장비·특성·조합·상대 지표)를 추가했다.
이 문서는 SQL 생성 프롬프트, 이후 평가의 정답 SQL 검수, 화면 안내에서 사용하는 정의의 기준이다.
현재 정의서·입출력 계약의 로컬 검토 단계이며 실제 Gemini 정확도 평가를 완료했다는 뜻은 아니다.

## 집계 단위와 분석 범위

- 참가자 출현은 `participants.participant_id` 한 행이다. 같은 사람이 여러 경기에 참가하면 각각의 출현으로 센다. 고유 이용자 수나 경기 수와 다르다.
- 기본 범위는 설정된 수집 시즌의 랭크 스쿼드(`matching_mode=3`, `matching_team_mode=3`), 최신 패치, 전체 티어다. 이름·기간·티어 등 질문에 명시된 조건은 선택된 기본 조건보다 우선한다.
- 최신 패치는 같은 시즌·모드의 수집 데이터에서 가장 큰 `(version_major, version_minor)`다. 시즌 ID, 이름 파일의 버전, 현재 공식 API 조회 시각으로 대신하지 않는다.
- 패치 비교는 각 패치의 분자와 분모를 별도로 계산한다. 다른 패치 표본을 한 분모에 섞지 않는다.
- 팀 단위 질문은 먼저 `(game_id, team_number)`로 중복 제거하고 팀을 분모로 표시한다. `team_number`만으로 서로 다른 경기의 팀을 합치지 않는다.
- 참가자 수가 적은 경기도 포함한다. 경기당 24명이나 8팀이라는 고정값으로 분모를 계산하지 않는다.
- 장비·특성 등 자식 JOIN으로 출현 수가 늘어나지 않도록 `EXISTS`, 사전 집계 또는 `COUNT(DISTINCT participant_id)`를 사용한다. 평균·분자도 중복되지 않게 집계 단위를 먼저 확보한다.

## 실험체 픽률 — Q-08

**픽률(%) = 해당 실험체의 참가자 출현 수 / 같은 분석 범위의 전체 참가자 출현 수 × 100.**

- 같은 패치·티어·기간 등 분석 범위 조건은 분자와 분모에 동일하게 적용한다.
- 계산 대상 실험체의 조건은 분자에 적용하고 분모에서 제외한다. 화면 또는 질문이 한 실험체를 지정했다는 이유로 분모도 그 실험체로 제한하면 안 된다.
- 전체 100출현 중 해당 실험체가 10출현이면 픽률은 10%다.
- 실험체가 등장한 경기 수 / 전체 경기 수는 별도의 경기 등장 비율이다. 이를 실험체 픽률이라고 반환하지 않는다.
- 반환 결과에는 대상 실험체의 출현 수와 전체 출현 수를 구분해 포함한다. 예시 별칭은 `picks`, `total_appearances`, `pick_rate`다.
- 분모가 0이면 `NULLIF`로 비율을 NULL로 반환하고 표본이 없다고 설명한다. 0%로 바꾸지 않는다.

예를 들어 패치 5.0의 전체 참가자 중 실험체 코드 1의 픽률을 계산하는 SQL 형태는 다음과 같다. 아래 코드는 예시이며 실제 질문의 코드·시즌·패치로 구성해야 한다.

```sql
WITH scope AS (
    SELECT p.participant_id, p.character_num
    FROM participants p JOIN games g ON g.game_id = p.game_id
    WHERE g.season_id = 41
      AND g.matching_mode = 3 AND g.matching_team_mode = 3
      AND g.version_major = 5 AND g.version_minor = 0
)
SELECT COUNT(*) FILTER (WHERE s.character_num = 1) AS picks,
       COUNT(*) AS total_appearances,
       100.0 * COUNT(*) FILTER (WHERE s.character_num = 1)
           / NULLIF(COUNT(*), 0) AS pick_rate
FROM scope s
```

## 승률·TOP 3 비율·평균 순위

| 지표 | 정의 | 반환 시 주의 |
|---|---|---|
| 승률 `win_rate` | `game_rank=1`인 참가자 출현 수 / 해당 분석 집단의 참가자 출현 수 × 100 | 팀 승률은 팀으로 중복 제거한 뒤 별도 계산 |
| TOP 3 비율 `top3_rate` | `game_rank<=3`인 참가자 출현 수 / 해당 분석 집단의 참가자 출현 수 × 100 | 승률과 구별 |
| 평균 순위 `average_rank` | 해당 분석 집단의 `game_rank` 평균 | 정규화하지 않음. 비교에는 승률과 TOP 3 비율을 함께 반환 |
| 표본 수 `samples` | 해당 분석 집단의 참가자 출현 수 | 결과 행 수·고유 이용자 수와 혼동하지 않음 |

승률·TOP 3의 분모는 분석 대상 집단이다. 실험체 픽률에서 대상 실험체 조건을 분모에서 제거하는 규칙을 승률에 적용하지 않는다. 모든 비율은 0~1 소수가 아닌 0~100의 백분율로 표시한다.

## 티어

경기 당시 `mmr_before`로 저장한 `tier`·`tier_division`을 사용한다. 최신 이용자 MMR로 과거 경기를 분류하지 않는다.

| 구간 | 경기 당시 MMR |
|---|---|
| 플래티넘 미만 | 3600 미만 |
| 플래티넘 | 3600 이상, 5000 미만 |
| 다이아몬드 | 5000 이상, 6400 미만 |
| 메테오라이트 | 6400 이상, 7600 미만 |
| 미스릴 이상 | 7600 이상 |

플래티넘 세부 단계 4→1의 하한은 3600/3950/4300/4650, 다이아몬드는 5000/5350/5700/6050, 메테오라이트는 6400/6700/7000/7300이다. 데미갓·이터니티는 MMR만으로 나누지 않는다. NULL MMR의 티어는 미확인이다. 티어 조건이 없으면 플래티넘 미만과 미확인 티어도 포함한다. Both remain in aggregates without a tier condition.

## 장비·특성·조합·상대 지표 (2026-10-14 사용자 결정)

시범 질문 검토(spec F-19)에서 사용자가 정한 정의다. 질문에 다른 기준이 명시되면 질문을 따른다.

- **코어아이템**은 전설·초월 등급 장비다. 경기 종료 시 장비(`participant_equipment.kind='FINAL'`)의 `grade` 5 이상이다. 장비를 맞춘 순서와 시각은 저장되지 않으므로 "첫 번째 코어아이템"처럼 순서를 묻는 질문은 답하지 않고 안내한다.
- **아이템 선택률(착용 비율)** = 그 아이템을 경기 종료 시 착용한 출현 수 / 조건을 만족하는 실험체 출현 수 × 100. 경기 도중 쓰다가 바꾼 장비는 셀 수 없다. `FIRST`는 슬롯별 첫 장비라 선택률에 쓰지 않는다. 답변에 "경기 종료 시 장비 기준"이라고 밝힌다.
- **아이템 성적 비교는 같은 등급끼리** 한다. 종료 시 장비는 오래 살아남을수록 등급이 높아 등급이 다른 아이템의 승률을 나란히 비교하면 생존 시간의 차이를 비교하게 된다. 등급(`participant_equipment.grade`)을 함께 반환하고 등급별로 묶는다.
- **특성 선택률**의 분모도 그 실험체 출현이다. 핵심 특성은 `participants.trait_first_core`다.
- **"좋다", "성능이 좋다"**는 한 지표가 아니다. 선택률(실험체는 픽률)·승률·TOP 3 비율·평균 순위·평균 RP 획득(`mmr_gain` 평균)을 함께 보여 준다. 선택률의 비중이 크다. 가중치를 임의로 정해 점수 하나로 합치지 않는다. 이 지표를 보여 주는 것은 데이터 제시이므로 "좋은 아이템", "같이 쓰면 좋은" 같은 질문은 예측·조언으로 거절하지 않고 이 지표로 답한다. 미래 결과의 예측과 개인 맞춤 조언은 여전히 하지 않는다.
- **"~와 같은 팀이면 좋니"**는 같은 `(game_id, team_number)`에 함께 있던 출현의 위 지표다. 표본은 대상 실험체의 출현이다.
- **"상대하기 좋다/힘들다"**는 `participant_matchups`의 킬 비중 = 그 상대 실험체에게 올린 킬 / (킬 + 그 상대에게 당한 데스) × 100이다. 어시스트는 상대별로 저장되지 않아 쓰지 않는다. 답변에 "그 상대를 킬한 비중으로 집계"라고 밝힌다. "X가 상대 팀에 있을 때"는 이와 달리 같은 경기의 다른 `team_number`에 X가 있었는지로 나눈 성적이며 직접 교전 여부와 무관하다.
- **"~을 제일 많이 당하는"**처럼 많이 겪는 정도는 횟수가 아니라 비율로 본다. 횟수는 많이 쓰이는 실험체가 위로 와 픽률 순위와 같아지기 때문이다. 8등은 `game_rank=8`이며 8팀 경기(`games.team_count=8`)의 출현만 분모로 쓴다.
- **패치 전후 비교와 상승·하락 순위**: "n 패치 전후"는 그 패치와 같은 시즌의 바로 앞 `(version_major, version_minor)`다. 이전 패치에 출현이 없는 신규 실험체는 상승·하락 순위에서 빼고 뺀 사실을 밝힌다.
- **추천 루트** (2026-10-17, V9): 루트 질문은 비공개·미조회 루트가 빠진 경향이다. 답변에 루트 정보가 있는 출현 수와 전체 출현 수(또는 비율)를 함께 밝힌다. `routes.v2_win_rate`·`v2_like`는 게임사가 집계한 값이므로 "루트 승률(게임사 집계)"처럼 이름을 붙여 경기 기록으로 계산한 승률과 구분한다. 루트의 경로·버전·승률은 조회 시점의 최신 상태다. 루트 사용 빈도는 `usage_count`가 아니라 분석 범위의 참가자 출현으로 센다. 루트 마지막 지역은 `route_paths`의 시즌·번호별 최대 `seq`다.
- **조합 재료** (2026-10-17, V9): "X가 들어가는 장비"는 `items.make_material_1` 또는 `make_material_2`가 X인 장비다. 직접 재료만 보며 재료의 재료는 따라가지 않는다. 현재 메타데이터 기준이다.
- **야생동물 처치**: `participants.kill_monsters`의 키는 1 닭, 2 박쥐, 3 멧돼지, 4 들개, 5 늑대, 6 곰, 7 위클라인, 8 알파, 9 오메가, 10 감마, 11 드론, 12 까마귀다(이름 테이블이 없어 2026-10-14 크레딧 대조로 확인). 변이 동물은 따로 세지 않으며 `credit_source`의 `KillMutant*` 값은 크레딧이지 마리 수가 아니다.

## 기간·이름·표본과 근거

- 한국 날짜·시간 조건은 `start_dtm AT TIME ZONE 'Asia/Seoul'`로 계산한다. `fetched_at`은 적재 시각이며 경기 시각이 아니다.
- 이름 테이블은 최신 확인 이름이다. 과거 경기 당시 이름·등급·능력치를 보장하지 않는다. 과거 FINAL 장비 등급은 `participant_equipment.grade`를 사용한다.
- 공식 이름을 확인하지 못한 코드는 LEFT JOIN으로 보존한다. 코드나 스킬 끝자리를 임의로 바꿔 이름을 만들어 내지 않는다.
- 각 분석 집단에 표본 수를 포함한다. 참가자 출현 30건 미만은 작은 표본 경고를 붙이고 결과를 그대로 보여준다. 경고 기준의 표본은 대상 집단의 출현 수이며 전체 픽률 분모로 대신하지 않는다.
- 표본 0은 자료 없음이다. 승률·TOP 3·픽률·평균 순위를 0으로 만들어 설명하지 않는다.
- 결과에 실제 적용한 조건·집계 단위·표본 수·확인 가능한 데이터 기준 시각을 표시한다. 기준 시각을 모르면 NULL로 남기고 요청 시각이나 최신 API 이름 확인 시각으로 대신하지 않는다.
- 요약은 실행 결과의 수치만 사용한다. 결과 밖의 조언·추천·인과관계·승패 예측을 덧붙이지 않는다. 적재된 표본을 전체 이용자 모집단의 통계라고 설명하지 않는다.
- 기준이 여러 갈래일 수 있는 지표(아이템 선택률의 종료 시 장비 기준, 상대 킬 비중, 횟수 대신 비율, 신규 실험체 제외, 8팀 경기만 분모)를 쓰면 요약에 쓴 기준을 한 문장으로 밝힌다.

## 미결정과 후속 검증

Q-08에서 결정한 것은 실험체 픽률이다. 아이템·특성 선택률은 2026-10-14 사용자 결정으로 위 "장비·특성·조합·상대 지표" 절을 따른다. 무기 선택률은 질문에 맞춰 그 실험체 출현을 분모로 쓰되, 다른 지표로 넓힐 때는 확인한다. 화면의 다중 선택·조건 확장(Q-05), 게임 내 패치 명칭 표시(Q-12)는 이 문서에서 결정하지 않는다. 실제 Gemini의 정의 준수·질문 정확도는 후속 종단 검증과 고정 평가에서 확인한다.
