## 문서와 달랐던 점

- 미확인
- 1 RPS 설정에서도 초기 실행 중 HTTP 429가 관측됐다. 일시적 누적 한도인지 키별 한도인지는 추가 측정이 필요하다.
- 공식 문서 예시 및 가상 샘플과 달리 `topRanks` 항목에는 `uid`/`userId`가 없다. 랭커별 `/v1/user/nickname?query=` 추가 호출이 필요하다.
- 닉네임 조회 응답의 식별자 필드명은 가상 샘플의 `uid`가 아니라 실제로는 `user.userId`다.
- 닉네임 조회는 HTTP 200 응답 안에 `code=404`를 담는 경우가 있었다. 초기 버전의 `api_call_log`는 transport status만 기록해 이를 200으로 남겼으며, 이후 버전은 JSON의 실질 `code`를 기록하도록 수정했다.
- 수집기 초기 버전은 nickname을 미리 인코딩한 문자열로 `RestClient`에 전달해 한글·일본어·한자 등이 이중 인코딩될 수 있었다. URI template 변수로 원문 nickname을 넘겨 UTF-8 인코딩을 한 번만 적용하자 기존 1위 한글 닉네임 조회와 적재가 성공했다. 따라서 과거 32건의 code 404 중 실제 미존재 닉네임과 인코딩 실패 건을 다음 전체 사이클에서 다시 구분해야 한다.
